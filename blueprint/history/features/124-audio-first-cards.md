# Feature: Audio-first cards (124)

**From build-plan:** feature 124
**Status:** verified (build, tests and browser evidence; Typed Answers and a Mix crossfade left to the user's manual check)

## Goal

Let the user mark a card **Audio first**, for openings whose visuals they already
know well, so they practise recognising the song alone. On `/study` and
`/listen` a marked card starts with its picture hidden while the audio plays. The
picture comes back once the answer is revealed, or when the user presses Show
video / `V`, for that showing only. The mark is stored on the card and stays
until it is cleared.

## Design reference

None needed. No new screen: one toggle in existing edit surfaces, one small
badge, and the existing Hide Video veil reused as is.

## Behaviour (the rule every step builds against)

A marked card's picture is hidden while all of these hold:

1. The card is marked `audioFirst`.
2. The user has not shown the video on this showing (`V`, the Video button in
   the display toggles, or Listen's Reveal).
3. Auto Reveal has not fired on this showing.
4. The answer is still hidden, **or** nothing was ever hidden on this showing.

**What "answer revealed" means on each surface:**

| Surface | Answer revealed when |
|---|---|
| Study, Typed Answers on | the result panel appears (`quizResult` set) |
| Study, manual Pass/Fail | Hide Info is lifted (`I`, or Auto Reveal) |
| Listen | Reveal, or Hide Info lifted |

Rule 4's second half covers the case where nothing hides the answer, such as
manual Study with Hide Info off. Without it, the picture would show at once and
the mark would do nothing. In that case the picture stays hidden until the user
shows it.

**Other details:**
- A repeat showing of the same card (after a fail, or Previous) hides the
  picture again.
- The session Hide Video toggle is never changed by any of this. On a marked
  card, `V` lifts that card's own veil first. When the card is not veiled, `V`
  toggles the session setting as it does today.
- An audio-only card has no video, so the mark does nothing for it. Its cover
  art stays as it is.

## In scope

- `Card.audioFirst` (boolean, default false), migration `0044`, on the shared
  card shape and every client copy.
- `POST /api/cards/audio-first` `{ ids (1-500), audioFirst }`, setting the
  flag without touching the schedule, history, `suspended` or `known`.
- Marking it:
  - Study's Edit card panel: a toggle that stays on the card. It does not
    advance, unlike Mark known.
  - The `/cards` inspector, shared with `/decks`.
  - The `/cards` bulk selection bar: Audio first / Not audio first.
  - `CardPreviewModal`'s edit mode. This is Listen's Edit card, and Preview's
    edit gets it as well.
- An "Audio first" badge on `/cards` table rows and in the inspector.
- The hiding behaviour on `/study` and `/listen`.

## Out of scope

- Preview playback. A marked card plays normally in Preview, as decided at
  intake.
- Party mode.
- Hiding the cover art on audio-only cards.
- A `/cards` filter for audio-first cards. It could be a later item.
- Any change to scheduling, `ReviewLog`, `CardTrack`, the status chip, or the
  session Hide Video default.

## Data / contracts

- **Load-bearing:** `Card.audioFirst` / `CardWithDetails.audioFirst: boolean`,
  placed right after `known` in the server shape and in every hand-kept client
  copy (F-09 convention).
- `POST /api/cards/audio-first`:
  - Body: `{ ids: number[] (1-500), audioFirst: boolean }`.
  - Returns `{ updated: number, notFound: number[] }`.
  - `400` on a bad body.
  - It does not return `statuses`, because the status chip does not depend on
    this flag.
- It is independent of `suspended` and `known`: setting one never clears the
  other.

## Testing

- The test gate is on:
  - Step 1 ships `cardAudioFirst.test.ts`.
  - Step 3 ships `audioFirst.test.ts`. The veil rule is the only part with

- The UI steps rely on browser evidence (the `playwright-cli` skill, or

- Unhappy paths:
  - The POST fails: the inline error appears and the toggle stays as it was.
  - A marked card has no video source: nothing changes.
  - A marked card fails to load: the existing error veil shows.
  - Turning off the mark mid-showing shows the picture at once.

## Notes for the AI

- Follow `coding-standards.md`: `<script setup lang="ts">`, scoped styles
  using `var(--token)` only, no inline styles, no commented-out code, no em
  dashes.
- Never write the per-card veil into the session `hideVideo` ref. It is
  derived state, so it cannot leak to the next card or survive a reload.
- Study's Auto Reveal watchers react to `hideVideo` changes
  (`onHideToggleChanged`). Lifting the audio-first veil must not set off a
  fake "manual reveal" of Auto Reveal, so keep the two apart.
- Changing this flag must not touch `ReviewLog`, `Card.box`, `CardTrack`, or
  the schedule.
- The 123a party-reset spec that was in this file is parked unchanged at
  `blueprint/drafts/123a-party-mode-reset.md`. Restore it after 124 completes.

## Post-build fix (2026-11-17, before merge)

Marking a card Audio first from Study's Edit card panel left the edit form
open, and an open form disables Missed and Got it, so the round could not be
graded. The form now closes after the toggle unless it holds unsaved path or
notes edits, and the closed panel shows an "Audio first" badge. Browser-checked:
Got it and Missed enabled after the toggle; a draft note keeps the form open.
